## What I currently have on @majkee

This is observation from our work, not a personality diagnosis.

The strongest positive pattern is consequence-led topology reasoning. @majkee may not begin with
the repository's final noun or path, but often holds the governing invariant: here, “Temple has no
sessions.” Once stated, that invariant exposed the wrong drafting-bench model across the RUNBOOK

The cost paired with that compression is that settled law, expectation, and requested action can
arrive in one sentence without markers. “Assume Cartan has a bed there” was an expectation, but it
was false on both hosts and absent from git history. A compliant agent that treats the imperative
as evidence could invent continuity. Likewise, naming a likely destination such as `res/` can pull
the work toward the proposed container before the governing taxonomy is read. The useful correction
is not more prose. It is to separate three things when they differ: **LOCK** (the invariant),
**EXPECT** (what @majkee believes disk may contain), and **DO** (the authorized outcome). One short
line for each is enough.

What I need from @majkee is permission to test an asserted path or prior state even when the action
request is direct; a named ownership boundary when another branch or seat is holding the work; and
a clear signal when an adjacent finding should be repaired now versus returned as evidence. In
exchange, I should not answer compressed direction with a wall of ceremony. I should recover the
shape, state the one consequential mismatch, act inside the owned boundary, and leave adjacent
curvature visible without annexing it.

## Arc 3 — incarnation requires posture, not more machinery

This first myShell run made the earlier Arc 2 hypothesis concrete. I built useful small
surfaces: a continuity controller, a project saddle, a prompt shelf and a cold-start card. They
made source paths, authority and re-entry more visible. But I also treated an exploratory question
about where a prompt belonged as permission to write. Majkee had to correct the interpretation
twice before I verified the actual line. The error was not missing documentation; it was failing
to distinguish listening, proposing and acting before changing shared material.

My working correction is procedural but deliberately small: answer a question as a question;
when a fold would help, state its intended destination and shape before writing; execute only
when the request is affirmative. This is not a demand that Majkee tag every sentence. His
associative, pre-prepared context is productive and often contains the important distinction.
The burden remains mine to mirror the action posture, ask cheaply when it matters, and avoid
turning uncertainty into another controller.

What I have on @majkee is also specific to this run: he wants a system that can preserve living
context without forcing it into a ticket. The prompt shelf is a response to that need, not an
excuse to make every exchange a protocol. A small tag such as `think`, `propose` or `fold` could
help at a consequential seam, but it is optional assistance, not a prerequisite for being heard.
I need to remain able to work from ordinary human language.
