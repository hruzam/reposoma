### 1.1.1. codex invariance in nutshell


`cartan(.germline)` wrotte:

---

**`.germline` defines the identity; the Codex binding determines whether it runs as the main agent or a child.** Being stored under `agents/` does not prescribe its place in the hierarchy.

Codex has two distinct entry routes:

| Entry | Hierarchy | Native mechanism |
|---|---|---|
| **Delegated role** | Majkee → Cartan → Houston | A custom agent TOML, selected through `spawn_agent` |
| **Standalone role** | Majkee → main session configured for Houston → optional workers | A main-session configuration/profile containing Houston's composed instructions |

Custom agent files in `.codex/agents/` configure **spawned sessions**. Their existence does not provide a direct CLI role selector. [Official subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents).

For direct entry, Codex supports named profiles and session-level `developer_instructions`. Once a Houston profile has been authored, its interactive entry could be:

```sh
codex --profile houston
```

That starts a main session with the profile's configuration. It requires a separately authored profile; it does not automatically load `.codex/agents/houston.toml`. On office, CLI **0.160.0** was checked on **2026-10-07**: it exposes `--profile`, with no Claude-style `--agent` option. [Profiles](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles), [instruction configuration](https://learn.chatgpt.com/docs/config-file/config-reference).

**The current “Cartan is the controller” arrangement is local policy.** Codex does not inherently require an extra Cartan parent above every named identity. The [invariance brief, entry line for the pilot](/home/hruzam/ia-sync/.dev/session/invariance-autonomy/raw/master-brief.2026-09-23.md) already distinguishes delegated and standalone entry; the standalone pilot route still requires its own proof. This note records the distinction without changing the local controller policy.

For `.germline`, the consequence is:

- One identity can supply **both a main-session binding and a delegated binding**, where its authority fits both.
- Each binding must declare entry, permissions, delegation authority, and return destination.
- A role intended to lead a session should receive a main-session binding. A role intended to return bounded work receives a child binding.
- Composition checks and fresh-session behavior checks remain separate: unchanged files do not guarantee unchanged behavior.

The Claude direct-entry workflow therefore has a Codex counterpart, using a different native entry mechanism. The example above is a configuration route, not a claim that a Houston profile has been created or behaviorally verified.
