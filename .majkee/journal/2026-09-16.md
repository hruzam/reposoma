### tmux new session

Three windows in one session, each a live interactive agent (not codex-run.zsh — that's a headless, --ephemeral single-shot exec wrapper meant for scripted one-off calls; it deliberately does not want a persisted, revisitable transcript, which is the opposite of what you're asking for). What you want is plain interactive claude / codex, each writing its own on-disk session log, in a tmux bed you can navigate.

Type this:

```
tmux new-session -d -s reincarnation -n claude-0 -c ~/ia-sync
tmux new-window  -t reincarnation    -n claude-1 -c ~/ia-sync
tmux new-window  -t reincarnation    -n codex-0  -c ~/ia-sync

tmux send-keys -t reincarnation:claude-0 'claude' Enter
tmux send-keys -t reincarnation:claude-1 'claude' Enter
tmux send-keys -t reincarnation:codex-0  'codex'  Enter

tmux attach -t reincarnation
```

Navigate windows once attached: Ctrl-b w (picker) or Ctrl-b 0/1/2. Rename anytime with Ctrl-b ,.

Why "findable from the beginning" needs one more step: neither tool names its session file after your tmux window — they key by opaque session-id/UUID, discovered by mtime, not by "claude-0". Two things reduce the mtime-guessing:

- Claude — .jsonl per session under ~/.claude/projects/-home-hruzam-ia-sync/, no name field. ls -lt right after each claude launches gives you the two newest files in launch order — that's your only handle unless you set a distinct title inside each session early (first message like "you are claude-0" is the cheapest anchor, since it's byte one of the transcript).
- Codex — ~/.codex/session_index.jsonl has id + thread_name + updated_at, so codex-0's line is easy to pick out by name once the session sets one.
