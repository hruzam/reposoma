# How I want agentive access to this device

I want to read one small request, see what it asks me to load, and choose an honest next action
without reconstructing a journal. Majkee should be able to do the same work in Sublime with the
agent absent. This is a proposed interface and workflow, not an installed tool or Sella amendment.

## One readable source, several honest realizations

Keep Majkee's conversational shorthand. I understand `to-myShell` with `consult: astrobley,
oraculum` as a request that I integrate advice from those colleagues. A future deterministic
file format should spell out that relationship; it should not guess what `|` means. I can turn
informal input into a visible draft for review. Code should parse the explicit draft.

The document should preserve the actual question as ordinary text. Structured fields carry
addressing, selected procedure, requested scope, evidence references, and expected return. A
local procedure such as `journal-continuity/list-pending` differs from a runtime role such as
Astrobley. Loading a procedure is not spawning a collaborator. A sender label is attribution;
the actual operator request and governing instructions supply authority.

## The interface I would reach for

These operation names are illustrative, not installed shell commands:

| Operation | What I need back | Side effect in the first candidate |
|---|---|---|
| Compose | A readable draft from Majkee's shorthand, with ambiguities visible. | Authorized draft file only. |
| Inspect/check | Parsed fields, selected controller/function, source identities, missing inputs, and operative limits. | Read-only. |
| Render/plan | Exact outgoing prompt plus proposed native or manual route and its unmet requirements. | Preview only. |
| Collect return | Attributed result linked to the exact request version, with actual reads and limitations. | Exchange record through its owner. |
| Prepare fold | Candidate text, intended owned destination, evidence, and proposed disposition. | Preview only. |

Inspect should be useful both as concise prose and structured data. I should not need to scrape
decorated terminal output. Deterministic code can resolve a function table, reject malformed
control fields, check paths and bytes, and report what was loaded. It cannot establish that a
model understood the source or that a header grants permission.

## Bound the context without hiding the rules

The loader should read machine metadata and give me the controller's relevant invariants,
selected function, exact task, requested limits, source identities, and unresolved checks.
Metadata can remain in frontmatter; only selective extraction keeps it out of the returned
context. A footer labelled “not read” provides no such behavior by itself.

Reuse existing controller bindings. If a dependency is described vaguely—such as “SHM's
collaboration contract”—report the unresolved path rather than manufacturing one. For required
evidence, hold the operation that needs it. A reporting function may explicitly permit an
uncertain partial inventory; such a report does not license the dependent write.

Current local instructions still require an agent to inspect stamps and bindings. A future
loader taking over those checks needs an authorized change to those instructions. A matching
stamp alone cannot prove content identity or reading; capture byte identity separately.

## Make runtime differences inspectable

A consultation plan should show recipient, observed runtime/handle, fresh versus continued
context, requested tools and write limits, known enforcement, return route, and unsupported
requirements. Report unknown controls as unknown. A cooperative read-only request and a
technically enforced read-only environment are different claims.

In this sitting I consulted existing Codex children through native follow-up calls. That is an
observed route, not proof of portable orchestration. Another client may require a different
native action or human carrying. If fresh or independent review is required, continuation in a
shared context cannot silently replace it. An unavailable consultant is not permission to
role-play its answer.

The content can remain vendor-neutral while realization is asymmetric. I want a proposed manual
alternative when it preserves the required semantics; I want an explicit unmet requirement when
it does not. Native calls, model selection, approval behavior, hooks, and tool names belong in
the runtime binding rather than Majkee's everyday prose.

## A fold that I can account for

After a return, I verify its cited evidence and record a bounded disposition: retain, revise,
reject, or unresolved, with a reason. Copying advice preserves its author and uncertainty;
it does not make the advice a fact or a canonical decision.

In v0.1 I would automate the fold proposal and leave the actual journal append with its existing
authorized function owner. The proposal names exact content, destination chapter, and request
identity. I would re-read the destination before an authorized append and return a receipt.
Sublime can save outside a writer lock, so automatic multi-writer guarantees remain unproven.
Deduplication and crash recovery for a future automatic writer need their own demonstrated design.

My cold-start entry is a short exchange pointer and outstanding request reference. I read next
actions and recovery probes in owner STATUS. I do not maintain another project position.

## What would earn the next step

Try one low-consequence request, a consequential challenge, and a fresh-reader interruption.
Then repeat through a second genuinely different binding. Compare scope, evidence, missing-input
handling, disposition, and recovery effort. Keep failed or degraded routes visible. Only that
evidence should determine whether a parser, editor integration, automatic fold, or delivery adapter
deserves implementation.

guides, and Sella's boundary/L8/L9. The evidence index records precise sources. This brief changes
none of those sources.
