# Qwen Code + OpenRouter — Operational Setup Guide
_Based on actual debug log analysis from ~/.qwen/debug/ — 2026-06-09_

---

## What this setup is

`qwen` CLI (`@qwen-code/qwen-code`) routing through OpenRouter's OpenAI-compatible endpoint
to reach `qwen/qwen3-coder:free`. The CLI speaks OpenAI protocol; OpenRouter proxies to Qwen.

---

## The single working `settings.json` structure

File: `~/.qwen/settings.json`

```json
{
  "$version": 4,
  "env": {
    "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENROUTER_AI_API_V1_D2BFDF91BF27": "sk-or-v1-..."
  },
  "modelProviders": {
    "openai": [
      {
        "id": "qwen/qwen3-coder:free",
        "name": "qwen/qwen3-coder:free",
        "baseUrl": "https://openrouter.ai/api/v1",
        "envKey": "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENROUTER_AI_API_V1_D2BFDF91BF27"
      }
    ]
  },
  "security": {
    "auth": { "selectedType": "openai" }
  },
  "model": {
    "name": "qwen/qwen3-coder:free"
  }
}
```

**Key rules:**
- `modelProviders` key MUST be `"openai"` — NOT `"openrouter"` (that string is rejected silently at startup with a WARN, model never loads)
- `envKey` value must exactly match a key in the `env` block
- The `QWEN_CUSTOM_API_KEY_*` hash suffix is generated by qwen's settings UI — do not invent a new one manually; use the existing hash or re-add via UI
- `security.auth.selectedType` must be `"openai"` to match the provider block

## Why it fails — known failure modes

### 1. Silent hang for 15+ minutes → 404 at the end

**Cause:** Free tier rate limit cascade.

Sequence in debug logs:
```
429 Provider returned error  → RETRY attempt 1 (~60s backoff)
429 Provider returned error  → RETRY attempt 2 (~90s backoff)
429 Provider returned error  → RETRY attempt 3 (~90s backoff)
404 Provider returned error  → FAIL (quota exhausted)
```

`qwen/qwen3-coder:free` on OpenRouter has a hard request-per-minute and request-per-day cap.
When you hit it, qwen does exponential backoff silently — no visible progress in the TUI.
The terminal looks frozen. It is not frozen; it is waiting. After all retries fail, you get a 404.

**Fixes (pick one):**
- Wait until the quota resets (usually per-minute or per-day depending on tier)
- Add credit to OpenRouter ($1–5 removes the free cap entirely for these request volumes)
- Switch to a less-popular free model with more remaining quota (see model alternatives below)
- Run `qwen -p "test"` in headless mode first to check if quota is available before launching TUI

### 2. Model never loads, qwen falls back to Gemini

**Cause:** Wrong `modelProviders` key — `"openrouter"` instead of `"openai"`.

Debug log signature:
```
[WARN] [MODEL_REGISTRY] Invalid authType key "openrouter" in modelProviders config.
Expected one of: openai, qwen-oauth, gemini, vertex-ai, anthropic. Skipping.
```

**Fix:** Edit `~/.qwen/settings.json` — change the `modelProviders` outer key to `"openai"`.
This was the bug in `install.md`'s suggested config snippet.

### 3. API key not found

**Cause:** The `envKey` string in `modelProviders` doesn't match any key in the `env` block,
or the `env` block was removed.

**Fix:** Re-add the API key through qwen's settings UI (the hash suffix is recalculated),
or manually ensure `env.<HASH_KEY>` matches `modelProviders.openai[0].envKey` exactly.

## Key wiring across your CLI family

Your `~/.config/zsh/.env/secrets.zsh` currently exports:

```zsh
export PIQL_API_KEY="sk-or-v1-..."       # OpenRouter key, canonical name
export OPENAI_API_KEY="$PIQL_API_KEY"    # alias for tools that read OPENAI_API_KEY
export OPENAI_BASE_URL="https://openrouter.ai/api/v1"
export OPENAI_MODEL="qwen/qwen3-coder:free"
```

| Tool | Reads from | Notes |
|------|-----------|-------|
| `qwen` CLI | `~/.qwen/settings.json` env block | Shell env is NOT read; key must be in settings.json |
| `claude` (Claude Code) | `ANTHROPIC_API_KEY` | Unrelated; your PIQL_KEY has no effect here |
| Tools using `OPENAI_API_KEY` | Shell env via secrets.zsh | Works when base URL is also set |
| Anything reading `OPENROUTER_API_KEY` | Not currently exported | Add `export OPENROUTER_API_KEY="$PIQL_API_KEY"` if needed |

`qwen` CLI does NOT read shell environment variables for API keys — it only reads its own
`settings.json` env injection. The exports in `secrets.zsh` are for other tools, not qwen.

## Model alternatives when free quota is exhausted

Check https://openrouter.ai/models?q=qwen for current availability. Common options:

| Model ID | Notes |
|----------|-------|
| `qwen/qwen3-coder:free` | Current default; good quality, heavy demand |
| `qwen/qwen3-8b:free` | Smaller, faster, usually less congested |
| `qwen/qwen2.5-coder-32b-instruct:free` | Older, sometimes has quota when qwen3 is exhausted |

To switch: change `model.name` and `modelProviders.openai[0].id/name` in `settings.json`.


## What to ignore

- `[WARN] getRepoTopLevel failed` — harmless, qwen started outside a git repo
- `[DEBUG] Failed to read IDE connection directory` — harmless, no IDE plugin connected
- `[INFO] Gemini client initialized` — qwen always initializes the Gemini client path even when using OpenAI provider; not a sign of misconfiguration
