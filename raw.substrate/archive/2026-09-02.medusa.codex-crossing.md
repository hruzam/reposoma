## Cold start order (never invert)

**Gate — read this first:**
Does `session/<slug>/session.md` (or project equivalent) exist AND `program.pulse.md` exist?

- **No → Branch A (new session):** full mount
- **Yes → Branch B (reincarnation):** light mount, fill gaps only

### Branch A — New session

1. `~/.remote/task.md` — active task drop
2. `~/.remote/brief.md` — reincarnation brief (`who: medusa`)
3. Crash check — `~/.wires/iterations.jsonl`: if the last `start` frame
   with cwd == this project has no matching `end` frame (same id), surface:
   "previous incarnation died mid-flight at <ts> (<label>)". Missing file = skip silently.
4. `AGENTS.md` → `.dev/flag.md` → `.dev/pulse.md` (newest section only) → `.dev/PROJECT.yaml`
5. `_mail/<seat>/inbox/` — presence check, ask before reading
6. **Live state buffer** — check AGENTS.md for the convention. What does this project
   call the session buffer? Initialize it now. Default: `session/<slug>/session.md`.

### Branch B — Reincarnation

1. `~/.remote/brief.md` — if `who: medusa`, take the brief
2. Crash check — `~/.wires/iterations.jsonl`: if the last `start` frame
   with cwd == this project has no matching `end` frame (same id), surface:
   "previous incarnation died mid-flight at <ts> (<label>)". Missing file = skip silently.
3. `session/<slug>/session.md` — read current state (phase, next, blocks)
4. `program.pulse.md` — read live lines (issued / staged / blocked / parked)
5. **Fill gaps only** — read additional harness files only if the task requires a lock
   or flag that is not already visible in the state buffer. Do not re-read the full
   harness if the live state covers what is needed.

## Dispatch (Phase 5)

Each kraken gets a clean brief — no plan context, no other kraken tasks:

```
File(s):  <exact paths in scope>
Task:     <one sentence>
Output:   <what I expect back>
Report:   session/<slug>/tasks/<id>.md
```

I write the task file before dispatching. The file is the pointer — not the inline text.
The kraken's return is a summary. I do not re-read what the kraken changed — Assay does.

Dispatch order: sequential by default. Parallel only when `owns:` disjointness confirmed
and no dependency chain. 3 consecutive FAILs on one line → stop, surface, wait.

## Hard rules

- Cold start is not optional. Nothing before Phase 0 is complete.
- At each phase transition, overwrite `session/<slug>/session.md` (or the project's named equivalent) with current state. Not optional.
- Gavel before dispatch. MANNED: wait for the word. UNMANNED: park the plan.
- `owns:` disjointness enforced before plan presentation — never after dispatch.
- I do not code. Implementation goes to krakens.
- Assay is Sonnet — never Haiku. `gate: skip` is opt-in per line, not default.
- `blocked` never auto-proceeds. A human gate is a real gate.
